# CoreBot — быстрый старт для первого пользователя

Документ для того, кто впервые разворачивает CoreBot и хочет за 30–60 минут
получить работающую систему: бот в Telegram + пул userbot-аккаунтов +
веб-панель оператора.

Если что-то не сходится — сначала смотрите раздел 9 «Если не работает».

---

## 0. Что вы получите в итоге

| Компонент | Что делает | Где живёт |
|-----------|-----------|-----------|
| **Control Bot** | Telegram-бот владельца: аккаунты, прокси, рассылки, нейрочат, база клиентов | процесс `python main.py` |
| **Worker accounts** | Userbot-аккаунты (Telethon). Они физически пишут в Telegram | пул внутри процесса бота |
| **Control Plane** | Веб-панель оператора: диалоги live, ручные ответы, CRUD, аналитика | `uvicorn` на `127.0.0.1:8081` |
| **Parser worker** | Парсинг каналов/групп/пользователей в аудиторию | встроен в панель или `python -m workers.parser_worker` |

Доступ к боту — **только у одного Telegram-ID** (`OWNER_ID`). Веб-панель наружу
не выставляется: смотрите её через SSH-туннель.

**Важно перед началом.** CoreBot — userbot. Использование автоматизации на
userbot-аккаунтах нарушает [Telegram ToS](https://telegram.org/tos) и может
привести к блокировке аккаунтов. Всегда используйте по одному прокси на
аккаунт, реальные задержки и соблюдайте местное законодательство. Ответственность
за использование — на вас.

## 1. Что нужно подготовить заранее

| Что | Где взять | Примечание |
|-----|-----------|-----------|
| `API_ID`, `API_HASH` | https://my.telegram.org → API development tools | Одна пара на все инстансы, менять не нужно |
| `BOT_TOKEN` | @BotFather → `/newbot` | Индивидуально для каждого инстанса |
| `OWNER_ID` | @userinfobot | Ваш личный Telegram-ID |
| Аккаунты | Tdata-папки ваших userbot-аккаунтов | Загружаются ZIP-архивом в боте |
| Прокси | Провайдер SOCKS5/HTTP | **Минимум один рабочий прокси на аккаунт** — иначе аккаунт не подключится |

Python 3.11+ (проверено на 3.12–3.14). Локальная разработка — Windows; прод —
Ubuntu 22.04/24.04.

## 2. Установка локально (10 минут)

```powershell
git clone https://github.com/<your-fork>/CoreBot.git
cd CoreBot

python -m venv venv311
venv311\Scripts\activate          # Linux/Mac: source venv311/bin/activate

pip install -r requirements.txt
copy .env.example .env            # Linux/Mac: cp .env.example .env
```

Заполнить в `.env` минимум эти 4 строки:

```env
API_ID=1234567
API_HASH=0123456789abcdef0123456789abcdef
BOT_TOKEN=123456789:AA...ваш_токен
OWNER_ID=123456789
```

Остальное — опционально (см. раздел 6).

**Про Windows и Tdata.** Конвертация Tdata → `.session` требует Python 3.11
(из-за `opentele`/PyQt5). Если рабочий venv на 3.12+, укажите путь:

```env
TDATA_CONVERTER_PYTHON=C:\путь\к\Python311\python.exe
```

При первом импорте Tdata CoreBot поднимет отдельный venv в
`data/tdata_converter_py311/` и поставит туда зависимости (нужен интернет).

## 3. Первый запуск (2 минуты)

На Windows рекомендуется единый launcher:

```powershell
start_corebot.bat
```

Он запускает Telegram-бота и Control Plane в отдельных окнах, затем открывает веб-панель. Проверка без запуска и принудительное обновление зависимостей:

```powershell
start_corebot.bat --check
start_corebot.bat --setup
```

Ручной запуск только Telegram-бота:

```powershell
python main.py
```

Что произойдёт при первом старте:

1. Создастся `data/corebot.db` (SQLite, WAL) и выполнятся авто-миграции.
2. Поднимутся фоновые потребители: `OutboundConsumer`, `BotCommandConsumer`,
   `WarmupRunner`, телеметрия.
3. Пул секций подключится (на первом старте пул пуст — это нормально).
4. В консоли появятся строки `Control Bot авторизован: @ваш_бот`.

Откройте Telegram, напишите своему боту `/start` **с аккаунта `OWNER_ID`**.
Должно появиться главное меню: `Аккаунты · База данных · Рассылка · Нейрочаттинг · Прокси · Прогрев · Статус системы`.

Если написать с другого аккаунта — бот ответит «Доступ запрещён». Так и должно быть.

## 4. Первые 5 шагов в боте (порядок важен)

### Шаг 1. Прокси (без него аккаунты не поднимутся)

`🌐 Прокси` → `➕ Добавить прокси` → формат `user:pass@host:port` (без логина/пароля: `host:port`).

Проверьте кнопкой теста. Рабочий прокси — обязательное условие: аккаунты без
рабочего прокси **специально не подключаются** (защита от бана: иначе вход в
Telegram идёт с IP вашего сервера).

### Шаг 2. Аккаунты

`👥 Аккаунты` → `📥 Загрузить Tdata (ZIP)`:

1. Заархивируйте **папку** с файлами Tdata (в ZIP должен быть либо `key_datas`,
   либо вложенная папка `tdata` — CoreBot найдёт корень сам).
2. Отправьте ZIP боту.
3. Бот распакует, конвертирует в `.session`, попросит выбрать прокси.
4. Каждый аккаунт получит статус, вы сможете задать имя в списке (`list_label`) — именно так его будете искать в панели.

Проверьте: `👥 Аккаунты` → `📋 Список аккаунтов` → у аккаунта должно быть
`✅ авторизован`. Если `❌` — аккаунт не подключился (обычно прокси), зайдите в
карточку и переподключите.

Отдельно: `🧹 Чистка / проверка прокси` — `🔄 Проверить прокси` и
`🔍 Проверка на спам-блок` (через `@SpamBot`) для всего флота сразу.

### Шаг 3. Клиенты (аудитория)

`🗄 База данных` → импорт `@username`-списка из TXT — по одному username в строке.
Бот покажет отчёт: сколько добавлено, сколько дублей, сколько некорректных.
Клиент ключуется по `telegram_user_id`, а не по username.

Далее классы-счётчики заполняются сами: `pulse` при первом касании, `alive`
через 60 минут, `accept`/`decline`/`stop`/`bl` — по реакциям.

### Шаг 4. Рассылка

`📬 Рассылка` → создать кампанию:

| Параметр | Что значит | Разумный старт |
|----------|-----------|----------------|
| Текст (+ варианты) | `{firstname}`, `{username}`, `{fullname}`, `{date}`, `{time}`, `{datetime}`, `{random4}`, `{link}` | 3–5 вариантов, они чередуются |
| `delay_between_messages` | пауза между сообщениями | 20–60 с |
| `delay_between_accounts` | пауза между переключением аккаунтов | 10–30 с |
| `messages_per_batch` | сколько пишет один аккаунт до ротации | 5–10 |
| `daily_limit` | потолок на аккаунт в сутки | 20–40 |
| `auto_stop_hours` | автостоп через N часов | 2–4 ч на старте |
| Аудитория | по классам / тестовый список TXT / все | начать с `test` |

**Тестовый режим** (`audience_mode=test`): каждый подключённый аккаунт пишет
каждому получателю из тестового списка — без дедупа. Это проверка «система
живая», а не боевая рассылка. Сначала всегда тест на 3–5 своих аккаунтах.

### Шаг 5. Нейрочат (опционально, но это основная ценность)

`🧠 Нейрочаттинг`:

1. `🔑 Ключ OpenRouter` — вставьте ключ с https://openrouter.ai/keys.
   Он шифруется (Fernet), если задан `OPENROUTER_KEY_ENCRYPTION_KEY`.
2. Глобальный toggle нейрочата.
3. Модель: по умолчанию `openai/gpt-oss-120b:free`, можно любую совместимую.
4. System-промпт: глобальный дефолт или свой на каждую рассылку.
5. Sampling-параметры (temperature/top_p/top_k/penalties) — или оставить дефолты.

Как это работает: входящее сообщение от клиента → проверка цепочки
`глобальный toggle → toggle рассылки → фильтры аккаунта/классов` → LLM получает
историю диалога → ответ отправляется с той же сессии, что писала рассылку.
LLM может добавить служебную метку: `[SEND_LINK]`, `[ACCEPT]`, `[DECLINE]`,
`[STOP]`, `[HATER]` — бот выполнит действие и обновит класс клиента.

Отказы логируются с причиной: `global_disabled`, `mailing_local_disabled`,
`worker_disconnected`, `client_class_bl`, `client_class_stop`.

## 5. Веб-панель оператора (необязательно)

Это интерфейс для второго человека: live-диалоги, ручные ответы, CRUD, аналитика.
Telegram-сессии остаются в процессе бота — панель их не трогает.

Добавьте в `.env` (панель без этих настроек не защищена!):

```env
CP_JWT_SECRET=<64 случайных hex — openssl rand -hex 32>
CP_BOOTSTRAP_ADMIN_USERNAME=admin
CP_BOOTSTRAP_ADMIN_PASSWORD=<сильный пароль>
BOT_DATABASE_URL=sqlite:////полный/путь/к/data/corebot.db
CP_AGENT_ENABLED=0
PARSER_EMBEDDED=0        # 1, если хотите парсинг внутри панели
```

Запуск (в отдельном терминале):

```powershell
uvicorn control_plane.main:app --host 127.0.0.1 --port 8081
```

Открыть `http://127.0.0.1:8081/panel/`, войти логином/паролем выше.

Разделы панели: Дашборд · Аккаунты · Диалоги (live через SSE) · Очередь ·
Парсинг · Рассылки · Клиенты · Группы · Прокси · Архив · Логи · Настройки.

Как оператор отвечает вручную: `#/dialogs` → выбрать аккаунт и клиента →
написать текст → отправить. Панель кладёт строку в `outbound_queue`, бот
подхватывает её в течение ~1.5 с и отправляет через живую Telethon-сессию.
Ручное сообщение попадает в историю диалога как `assistant`, поэтому LLM его
увидит, если аккаунт вернут в режим AI.

**Роли:** `super_admin` (полный), `tenant_admin`, `tenant_viewer` (read-only).

## 6. Переменные окружения

Обязательные: `API_ID`, `API_HASH`, `BOT_TOKEN`, `OWNER_ID`.

Часто нужные:

| Переменная | Смысл | Дефолт |
|-----------|-------|--------|
| `DATABASE_URL` | БД бота | `sqlite+aiosqlite:///…/data/corebot.db` |
| `LOG_LEVEL` | Уровень логов | `INFO` |
| `CONTROL_BOT_PROXY_*` | Прокси для самого Control Bot | не задан |
| `OPENROUTER_API_KEY` | Ключ OpenRouter | не задан |
| `OPENROUTER_KEY_ENCRYPTION_KEY` | Fernet-ключ для шифрования ключа в БД | не задан (хранится открыто) |
| `NEUROCHAT_ENABLED` | Глобальный fallback-флаг нейрочата | `1` |
| `DEFAULT_NEURO_MODEL` | Модель по умолчанию | `openai/gpt-oss-120b:free` |
| `NEURO_MAX_CONCURRENT` | Параллельные LLM-запросы | `8` |
| `NEURO_HISTORY_LIMIT` | Глубина истории диалога | `20` |
| `MAILING_BASE_UTC_OFFSET` | Сдвиг для `{date}`/`{time}` | `0` |
| `BANDWIDTH_SAVER_MODE` | Экономия трафика (доп. запросы не делаются) | `1` |
| `WARMUP_ENABLED` | Прогрев аккаунтов | `0` |
| `PARSER_EMBEDDED` / `PARSER_POLL_SEC` | Парсер внутри панели / период опроса | `1` / `2` |
| `CP_AGENT_ENABLED` / `CP_INGEST_URL` / `CP_AGENT_TOKEN` | Телеметрия бота в панель | `0` |

Полный список с комментариями — `.env.example`. Панельные переменные, которых
там пока нет: `CP_ACCESS_TTL_MIN`, `CP_REFRESH_TTL_MIN`, `CP_RETENTION_DAYS`,
`CP_INGEST_SUPPRESSION_SEC`, `CP_AGENT_FLUSH_SEC` — добавляйте только если
действительно нужно их менять.

## 7. Ежедневная шпаргалка

Бот (команды в чате с ботом от `OWNER_ID`): `/start`, `/help`, `/status`.

| Задача | Где |
|--------|-----|
| Статус системы | `📊 Статус системы` или `/status` |
| Запустить рассылку вручную | `📬 Рассылка` → старт, либо `/start_mailing` (берёт рассылку `#1`) |
| Проверить прокси флота | `🧹 Чистка / проверка прокси` → `🔄 Проверить прокси` |
| Спам-блок | `👥 Аккаунты` → карточка → `👤 @SpamBot`-проверка |
| Остановить всё | `📬 Рассылка` → стоп (или панель → Рассылки → stop) |

Правила выживания флота:

- один аккаунт = один прокси, никогда не «напрямую с сервера»;
- не поднимайте `messages_per_batch` и `daily_limit` выше ~10 / 40 в первые дни;
- `auto_stop_hours` всегда задавайте — не оставляйте кампанию без потолка;
- любой FloodWait и `@SpamBot`-блок = аккаунт в паузу, разбираться отдельно;
- меняйте тексты (варианты), а не гоняйте один и тот же.

## 9. Если не работает

| Симптом | Причина и что делать |
|---------|----------------------|
| «Отсутствуют обязательные параметры: …» | `.env` не заполнен → раздел 1 |
| «Доступ запрещён» в боте | Пишете не с `OWNER_ID` |
| Аккаунт `❌` или не подключается | Нет прокси / прокси мёртвый — проверьте, это защита от бана |
| Импорт Tdata падает | Нужен Python 3.11: задайте `TDATA_CONVERTER_PYTHON` |
| Ручное сообщение висит в `pending` | Пул аккаунтов не подключён, статус аккаунта не `AI_ACTIVE`/не авторизован |
| Нейрочат молчит | Проверьте по порядку: глобальный toggle → toggle рассылки → классы клиента (`bl`/`stop`) → ключ OpenRouter → модель |
| Панель открывается пустой | `BOT_DATABASE_URL` указывает не туда (нужен абсолютный путь) |
| Не входит в панель | Логин/пароль — это `CP_BOOTSTRAP_*`, **не** пароль владельца бота |
| `database is locked` | Второй процесс держит БД; WAL уже включён, уменьшите параллельность |

Аварийный порядок: остановить рассылку → `📊 Статус системы` → посмотреть
`logs/error.log` → проверить прокси → только потом менять код/настройки.

## Проверяемая карта запуска

### Локально

1. Активируйте Python 3.11 virtualenv и установите `requirements.txt`.
2. Скопируйте `.env.example` в `.env`; задайте `API_ID`, `API_HASH`, `BOT_TOKEN`, `OWNER_ID`.
3. Запустите `python main.py`.
4. Опционально запустите панель: `uvicorn control_plane.main:app --host 127.0.0.1 --port 8081`.
5. Проверьте `http://127.0.0.1:8081/health/ready` и `python -m pytest -q`.

### Режим парсера

Используйте только один вариант:

- `PARSER_EMBEDDED=1` — parser-loop запускается вместе с Control Plane;
- `PARSER_EMBEDDED=0` — parser-loop запускается отдельно командой `python -m workers.parser_worker`.

Одновременный запуск обоих вариантов запрещён: это создаёт два конкурирующих потребителя очереди.

### Перед VPS-запуском

```bash
openssl rand -hex 32
chmod 600 /opt/corebot/app/.env
curl --fail http://127.0.0.1:8081/health/ready
journalctl -u corebot.service -u corebot-cp.service -n 100 --no-pager
```

Не продолжайте установку, если `CP_JWT_SECRET` или пароль панели содержат `change-me`, либо используются `admin/admin123`.
