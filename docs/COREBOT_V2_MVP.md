# CoreBot V2: первый рабочий срез

## Что доступно

- Главная страница `/` с переходом в рабочий кабинет `/panel/`. Визуальный язык собственный: тёмная зелёная палитра, редакционная типографика и сценарные карточки.
- Нейрокомментинг и групповые ответы: оператор выбирает аккаунт, вставляет ссылку на сообщение группы, которой управляет, и контекст. Поддерживаются публичные и приватные обсуждения. OpenRouter готовит черновик. Оператор редактирует и одобряет его. Команда отправки идёт через процесс воркеров; комментарий отвечает на конкретное сообщение группы.
- Состояние аккаунтов: общая перед каждой отправкой проверка активности, явных ограничений Telegram, ручной паузы и дневного бюджета. Попытки резервируются атомарно в БД; остановка и журнал сохраняются после перезапуска. Возобновление после ограничения требует действия администратора.
- Существующие сценарии CoreBot: личные диалоги с AI и ручными ответами, рассылки, парсинг, CRM и прогрев. Реакции прогрева учитывают общий бюджет действий, а прогрев пропускает аккаунты, ожидающие проверки.
- Бот: короткое главное меню «Аккаунты / Прокси / Рассылки / БД / ИИ», единый ZIP-импорт одной или нескольких TData, листы прокси с проверкой, страничный список аккаунтов и рассылок, редактор шаблонов профиля и независимые наборы имён, bio и фото для случайного применения к выбранному аккаунту.
- При сетевом отказе SOCKS5 бот выбирает свободный прокси из того же runtime-листа и подтверждает подключение аккаунта через Telegram. Привязка выполняется атомарно: один запасной прокси не достанется двум аккаунтам. Фоновый цикл обнаруживает потерю соединения; в рассылке замена выполняется после завершения неудачной попытки отправки. Сообщение с неизвестным результатом доставки автоматически не повторяется.

## Локальный запуск

Следуйте `README.md` и `.env.example`. Нужны учётные данные Telegram и ключ OpenRouter для генерации черновиков. Запустите `python main.py` и `uvicorn control_plane.main:app --host 127.0.0.1 --port 8081 --no-access-log` либо используйте `start_corebot.bat`. Панель открывается по `http://127.0.0.1:8081/panel/`, главная — по `http://127.0.0.1:8081/`.

База создаёт таблицы `account_safety_states`, `account_safety_events` и `engagement_drafts` через текущую процедуру `Base.metadata.create_all`. Перед запуском на реальных данных сделайте резервную копию БД и `.session` файлов. Не открывайте управляющий порт напрямую в интернет; используйте SSH-туннель или HTTPS с ограниченным доступом.

## Порядок проверки сценария

1. Добавьте и авторизуйте аккаунт, настройте его прокси и положительный дневной лимит.
2. В настройках инстанса укажите OpenRouter API key.
3. В «Нейрокомментинг» вставьте ссылку вида `https://t.me/your_discussion/123` или `https://t.me/c/1234567890/123` и текст сообщения. Ссылка должна вести на сообщение группы, а не на пост канала.
4. Проверьте черновик, при необходимости поправьте его и нажмите «Одобрить и отправить». Итог виден в списке черновиков.
5. В «Состояние аккаунтов» проверьте бюджет и журнал. При ограничении Telegram аккаунт останавливается; после ручной проверки администратор может возобновить отправку.

## Границы первого среза

- Генерация комментариев требует ручного добавления контекста и одобрения. Автоматическое чтение публикаций и полностью автономная массовая отправка не входят в этот сценарий.
- Поддерживаются ссылки на сообщения публичных групп и приватных обсуждений `t.me/c/...`. Аккаунт отправителя должен состоять в приватной группе; доступность ссылки и права Telegram проверяются при отправке.
- Декларация «управляю обсуждением» вводится оператором; Telegram-права владельца группы пока не проверяются автоматически.
- Защита аккаунта реагирует на известные сигналы и останавливает действия. Она не гарантирует отсутствие блокировок и не предсказывает решения Telegram.
- Массовая смена 2FA пока не доступна. Индивидуальная установка не завершает другие Telegram-сессии и удаляет сообщения с паролем из чата после получения. Пароль не следует отправлять в публичный чат.
- Шаблон или случайный профиль применяется одной кнопкой к выбранному аккаунту. Массовое применение ко всей группе ещё не добавлено.
- Сквозной прогон на VPS остаётся отдельным этапом; локальные живые проверки перечислены ниже.

## Живой прогон 25 сентября 2026 года

- Три предоставленных аккаунта подключились через закреплённые SOCKS5 и прошли `is_user_authorized`.
- Один из этих прокси в следующих стартах отвечал нестабильно: один ответ занял 9,6 с, затем произошёл `Host unreachable`. Для аккаунта подобран свободный прокси того же листа с выходом в Колумбии; на нём авторизация прошла. После замены и повторного запуска бот подключил 3 из 3 тестовых аккаунтов. Лимит предварительной проверки увеличен с 8 до 15 с.
- После очередного запуска все три аккаунта опять подключились, но позднее Telethon зафиксировал `Host unreachable` и исчерпал пять попыток переподключения через один из назначенных прокси. Длительная устойчивость прокси и восстановление соединения требуют отдельного прогона; стартовые `3/3` не следует считать подтверждением непрерывной работы.
- Реализована ротация после сетевой ошибки: после смоделированного отказа текущего прокси аккаунт #7 получил незанятый прокси из своего листа `colombia`, реально подключился и прошёл `is_user_authorized`. После штатного перезапуска бот подключил 3 из 3 колумбийских аккаунтов. Проверены исключение занятых прокси, разделение листов, повторная попытка после неработающего кандидата и отсутствие повторной отправки сообщения с неизвестным результатом. Длительный прогон фонового восстановления ещё нужен.
- Контрольная рассылка из одного аккаунта по двум явно указанным тестовым username завершилась: 2 отправлено, 0 ошибок; сообщение обнаружено в обоих чатах получателей.
- Созданы закрытая тестовая группа и закрытый канал с привязанным обсуждением. Ответ на сообщение группы и комментарий к публикации канала отправлены через `Worker.send_message_with_typing`; комментарий отображается под публикацией.
- На первом вызове AI черновик не создался: прежний бесплатный идентификатор модели перестал обслуживаться OpenRouter. Значение по умолчанию заменено на актуальный бесплатный маршрут `openrouter/free`. Повторный вызов через авторизованный API панели создал черновик для приватного обсуждения; после просмотра текста и одобрения бот отправил комментарий, а Telegram показал «2 Comments» под тестовым постом.
- Нейрочат в ЛС проверен на двух тестовых аккаунтах через реальную очередь и Telethon: входящее сообщение вызвало AI-ответ, получатель увидел его в Telegram. Этот прогон обнаружил, что тестовая рассылка с повторно использованным ID подхватила файл промпта удалённой кампании. Старый файл сохранён в архиве; создание новых рассылок теперь архивирует такой файл до активации новой кампании. Повторный живой прогон ответил нейтральным «Получено.» без содержимого старой кампании.
- Ответ «Получено.» дополнительно найден в чате получателя. История нейрочата теперь сохраняет ответ ассистента только после подтверждённой отправки, чтобы не показывать неотправленный текст как доставленный.
- Парсер участников проверен на собственной закрытой группе: задача создана через API панели, обработана ботом на уже подключённом аккаунте и завершилась с 3 участниками, 0 ошибок. Числовой ID закрытой группы передаётся Telethon как число. При `PARSER_EMBEDDED=0` бот запускает парсер вместе с собой и использует свои активные сессии, не открывая их повторно в другом процессе.
- Бот допускает несколько явно перечисленных владельцев через `BOT_ADDITIONAL_OWNER_IDS`, сохраняя прежний `OWNER_ID`. Основной аккаунт проверен живым `/start`: открылись пять разделов; проверен путь «Аккаунты → Управление → Список → карточка» с кнопками возврата. Пересланный контакт, ошибочно принятый сначала за основной ID, сразу исключён из настроек до повторного запуска бота.
- Полный локальный прогон после ротации в проектном `.venv`: `329 passed`, два предупреждения из зависимостей.
- Результат подтверждает локальный путь от AI-черновика до реальной отправки. Импорт нового TData ZIP через новый интерфейс, массовое применение профилей и длительная стабильность ещё не прошли такой же живой прогон.
