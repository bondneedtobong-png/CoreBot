# Проверка подпунктов GramGPT против CoreBot

Срез 2026-09-26. Основа — §3 `gramgpt/feature-inventory-complete.md`; статусы относятся к текущему рабочему дереву CoreBot. **Есть** означает локально проверенный сценарий; **частично** означает действующий фрагмент без полного набора полей, состояний или проверки полного пути; **нет** означает отсутствующий исполняемый сценарий. Для отмеченных ниже новых массовых операций живого массового прогона не было. Подробный порядок работ — [GRAMGPT_IMPLEMENTATION_MATRIX.md](GRAMGPT_IMPLEMENTATION_MATRIX.md). Функции контакта допускают только собственную аудиторию с подтверждённым правом; функции сообществ — только управляемые площадки. Числа и обещания GramGPT не переносить как правила Telegram.

## 3.7 Нейродиалоги — частично

| Подпункт | Статус | Код / пробел |
|---|---|---|
| Единый inbox, поиск, ручной ответ, история и автоответ/наблюдение | частично | `business.py`, `outbound_consumer.py`, `services/neurochat/`, `web-panel/main.js`; общий inbox загружает все аккаунты страницами по 50, фильтрует ожидающие и непрочитанные по оператору, ищет ID, username и сохранённые реплики. Ручной ответ и история открываются в карточке выбранного аккаунта; для очень большой БД нужны индексированный поиск и курсор вместо offset (сейчас максимум 10000) |
| Непрочитанные/ожидающие, edit/delete сообщения, звук, CSV/TXT | частично | «Ждёт ответа» и персональное «непрочитано» фильтруются в inbox; прочтение сохраняет курсор оператора. SSE обновляет список выбранного аккаунта, входящее сообщение подаёт включаемый браузерный звук. CSV/TXT выгружаются постраничным потоком без потолка 10 000 строк; edit/delete отсутствуют |
| Сценарий: промпт, стиль/язык, знания, контекст, задержка/часы/лимиты/stop | частично | Промпт, контекст, OpenRouter и OpenAI-совместимые профили провайдеров, локальные флаги и stop. База знаний на рассылку: CRUD с RBAC, включение/выключение, выбор до 3 фрагментов по ключевым словам, подстановка в живой ответ и тест промпта. Часы AI-ответов по IANA зоне рассылки проверяются перед LLM и Telegram RPC. Суточный лимит на рассылку сохраняется в SQLite, атомарно резервируется перед LLM и фиксирует успешный текст или ссылку после Telegram; сбой процесса может консервативно удержать слот до конца локального дня. Семантического поиска и отдельных лимитов по типам действий нет |
| Тест диалога и сравнение версии промпта | есть | Панель сравнивает сохранённый и кандидатный промпт на 1–3 последовательных синтетических репликах с отдельным контекстом ответов, без сохранения и Telegram-отправки; версии промпта сохраняются и восстанавливаются |
| RBAC и аудит просмотра/экспорта | есть | Выгрузка требует write-RBAC и журналирует оператора/диалог/формат/число строк; API просмотра журналирует доступ с интервалом 15 минут. Журналы не содержат текст; чтение журналов требует write-RBAC |

| Ручной/авто план, этапы, календарь, timezone и окна | частично | Профиль задаёт IANA-зону и часы работы; действие планируется только вне них. Этапы/календарь отсутствуют |
| Длина сессии, паузы, распределение старта | частично | Между действиями не менее 30 минут, следующий запуск и jitter сохраняются в БД; распределённого календаря нет |
| Чтение, профили/истории, реакции, опросы, вступления, свои сообщения | частично | Безопасный пресет читает диалоги и явно заданные публичные чаты, реакция только по отдельному разрешению; массовых вступлений и искусственных сообщений нет |
| Лимит час/день/тип, прогресс, причины skip, отчёт и stop | частично | Дневной cap профиля, лог, отчёт 7/30 дней, локальный preview бюджета/времени/причины и выключатель аккаунта есть; per-type/час и этапы отсутствуют |

## 3.15 ИИ-защита аккаунта — частично

| Подпункт | Статус | Код / пробел |
|---|---|---|
| Классификация RPC, auth/proxy/restriction раздельно | частично | FloodWait/slow mode и новая проверка SOCKS5/auth различаются; полной модели сигналов нет |
| Постоянный gate, scope, stop/quarantine и события | частично | `account_safety_state/events`, `account_chat_cooldowns`, `reserve_send` покрывают текст и реакцию прогрева; read-действия прогрева проверяют остановку. Другие действия ещё не все покрыты |
| Возобновление после срока и проверки оператором | частично | Срок и ручная команда есть; процесс бота свежо проверяет SOCKS5 и авторизацию до открытия gate, прерывание оставляет блокировку. Нужна более подробная типизация ограничений и живой сценарий |
| Консультативный ИИ-разбор наблюдаемых сигналов | частично | Оператор может запросить анализ обезличенного состояния/событий/проверок; ИИ не снимает ограничения и не прогнозирует блокировку |
| «ИИ-предсказание» и имитация набора/опечаток как защита | нет | Заявление GramGPT не валидировано; не критерий приёмки |

## 3.16 Другие возможности — частично

## Сквозная проверка

До закрытия каждого подпункта нужен тест пути **настройка → preview → очередь/запуск → stop → результат → история**, включая ошибку Telegram, отсутствие права на контакт, ограничение аккаунта и восстановление после рестарта. Для историй, реакций и коммуникаций проверять на собственных тестовых целях; парсер видимой аудитории не даёт права на рассылку.
